# DeepSeek Harness 桌面端

把 DeepSeek Harness 装进一个原生窗口的 PC 客户端:下载一个 exe,双击就能用,
不用再开浏览器标签页,也没有烦人的命令行黑框。

---

## 🎯 这是什么

- **给谁用**:电脑上已经在用 DeepSeek Harness(DSH)的人,想省去"开浏览器、
  切标签页"的麻烦。
- **能做什么**:用单独的原生窗口打开你本机的 DSH 界面(`http://127.0.0.1:3080`),
  你的 DSH 服务没启动时,它会自动帮你启动;退出时自动判断关不关服务。
- **不做什么**:它**不含 DSH 服务本体**,只是一个"窗口外壳"——所以使用前,
  你的电脑上需要已经能运行 DSH(只装了它、没装 DSH 是不行的,见下文)。

---

## 📥 怎么下载和安装(普通用户)

1. 打开本仓库页面,点右侧 **Releases**;
2. 下载最新的 `DeepSeek Harness 桌面端 x.x.x.exe`;
3. **放到一个专门的文件夹里**(比如新建 `D:\dsh-desktop`),
   建议别放在"下载"文件夹里,原因见 FAQ;
4. **双击运行**。

> 🛡️ **第一次双击如果弹"Windows 已保护你的电脑"**:
> 这是对未签名程序的正常提示,点 **"更多信息" → "仍要运行"** 即可,以后不会再问。

### 使用前提:先安装 DSH(只需一次)

桌面端只是窗口外壳,首次使用前需要装上 DSH 服务本体——通过 npm 安装,不需要会编程:

1. **安装 Node.js**:打开 https://nodejs.org/zh-cn ,下载 **LTS** 版安装包,一路"下一步";
2. **打开命令提示符**(`Win+R` → 输入 `cmd` → 回车),粘贴并运行:
   ```cmd
   npm install -g @deepseek-ai/dsh
   ```
   看到输出出现 `@deepseek-ai/dsh` 即安装成功;
3. **验证(可选)**:输入 `dsh -V`,能打印版本号就装好了。

**不确定自己装没装?** 浏览器访问 `http://127.0.0.1:3080`,能打开就是装好了。

> 装好后直接双击 exe 即可,应用会自动用 `dsh web` 启动本地服务。
> 首次打开若显示**安装引导页**,说明系统 PATH 里找不到 `dsh`(自定义过 npm 目录时常见):
> 在命令提示符输入 `where dsh` 找到 `dsh.cmd` 完整路径,设置环境变量 `DSH_CMD`
> 指向它,然后重新打开应用。

---

## 🚀 第一次打开会发生什么

1. 窗口先出现,显示"正在启动本地服务";
2. 应用自动检测 DSH 服务是否在运行;
3. 没在运行 → 自动帮你启动(全程隐藏,没有命令行窗口、不弹浏览器);
4. 服务就绪 → 自动进入 DSH 界面,完事。

**之后每次使用**:双击 exe → 直接进界面,就这么简单。

小知识:

- **退出时智能关服务**:如果你用浏览器也在访问 DSH,退出桌面端时会**保留服务**;
  只有确认"只有桌面端在用"时才关闭服务。你手动开的 DSH 永远不会被它动。
- **管理界面**:窗口顶部菜单有 视图 → 后退/前进/刷新/回到首页、开发者工具 (F12)、
  放大缩小;点外部链接会交给系统默认浏览器打开,不会在应用里乱跳。
- **只有一个窗口**:重复打开只会把已有窗口唤到前台,不会开出一堆窗口。

## 💾 你的数据在哪里(备份/迁移)

会话数据、缓存、Cookie 都保存在 **`userdata/` 文件夹**里:

- exe 版:在 **exe 旁边的 `userdata/` 文件夹**;
- 安装版/解压版:在系统 `%APPDATA%\dsh-desktop`。

想备份或换电脑,把这个文件夹一起拷走即可。

## ❓ 常见问题 (FAQ)

**Q:打开后显示"需要先安装 DeepSeek Harness"?**
说明本机还没有 DSH,应用无法自动启动服务。三选一:
1. 按上文「先安装 DSH」的步骤装好 DeepSeek Harness;
2. 把 `dsh` 所在目录加入系统 PATH;
3. 设置环境变量 `DSH_CMD` 指向 `dsh.cmd` 的完整路径(用 `where dsh` 查路径)。

做完后**完全退出并重新打开应用**。如果你已经手动启动了 DSH 服务,
点页面上的"重新检测"就能直接进入界面。

**Q:一直停在"正在启动本地服务"?**
先确认 3080 端口没被别的程序占用;再点"立即重试"。还不行的话,把应用数据目录
(`userdata/`)下的 `main-error.log` 发给我看。

**Q:为什么建议把 exe 放到专门文件夹?**
因为 exe 版的数据(`userdata/`)会创建在 exe 旁边。放在"下载"文件夹里,
哪天清空下载就一起没了;专门的文件夹更好管理、好备份。

**Q:exe 会被杀毒软件拦吗?**
未签名的新程序偶尔会被 Windows Defender 或第三方杀软误报,点"允许/仍要运行"即可。
如果被直接删掉,给杀软加个信任目录再下一次。

**Q:双击后没反应 / 鼠标转圈后无事发生?**
请确认你下载的是最新版 exe(早期版本有过一个启动 bug,已修复)。
如果还是不行,把 `userdata/` 下的 `main-error.log` 内容发给我排查。

**Q:会泄露我的会话记录、API key 吗?**
**不会。** 应用本身不含任何密钥;你的会话数据只存在 **本机**的 DSH 服务数据目录和
你的 `userdata/` 里,全程不会上传到 GitHub 或任何地方。

**Q:能换端口/地址吗?(高级)**
可以,设置环境变量 `DSH_URL` 后再启动,例如
`set DSH_URL=http://localhost:3081 && 双击exe`。一般用户不需要动。

**Q:怎么卸载?**
它是免安装的绿色软件:退出后删掉 exe 和旁边的 `userdata/` 文件夹即可。
如果 `%APPDATA%\dsh-desktop` 也存在(安装版),一并删除。

## 🧑‍💻 附录:开发者/从源码运行(非普通用户)

想自己改代码、跑源码版时:

```bash
git clone https://github.com/Ary66101/dsh-desktop.git
cd dsh-desktop
npm install     # 首次,需 Node.js ≥ 20
npm start
```

常用环境变量:

| 变量 | 作用 | 示例 |
|------|------|------|
| `DSH_URL` | 修改 DSH 服务地址 | `set DSH_URL=http://localhost:3080 && npm start` |
| `DSH_CMD` | 指定 `dsh.cmd` 完整路径(不在 PATH 里时用) | `set DSH_CMD=D:\tools\dsh.cmd && npm start` |
| `DSH_SPAWN` | 完全自定义拉起服务的命令行 | `set DSH_SPAWN=my.sh --flag && npm start` |

打包成免安装 exe(产出于 `dist/`):

```bash
npm run dist     # electron-builder --win portable --publish never
```

命令行自检(不开窗口,自动退出):`npm run smoke`,结果写 `smoke-result.txt`。

源码版数据目录用的是项目内 `userdata/`;打包版规则见上文"你的数据在哪里"。
